## Design: AP Startup Integration Flow

### Current ap_entry() Sequence
1. cpu::early_init() - FPU/SSE, protections
2. Get current LAPIC ID
3. gdt::init_ap_per_core() - Load GDT/TSS
4. cpu::set_gsbase() - Enable per-core data
5. interrupts::init_ap_interrupts() - Load IDT
6. Publish handshake to BSP
7. halt::halt_loop() ← PROBLEM: AP just halts!

### New ap_entry() Sequence (2.3)
1. cpu::early_init()
2. Get LAPIC ID
3. gdt::init_ap_per_core()
4. cpu::set_gsbase()
5. interrupts::init_ap_interrupts()
6. **scheduler::init_per_cpu_scheduler()** ← NEW
7. **scheduler::spawn_idle_task()** ← NEW
8. **scheduler::run()** ← Enter scheduler loop instead of halt
9. Publish handshake
10. Run tasks until shutdown

## Implementation Steps

### Step 1: Extend PerCpuData (percpu.rs)
Add scheduler-related fields:
```rust
pub struct PerCpuData {
    // ... existing fields ...
    pub current_task_id: u32,          // Current task ID
    pub scheduler_initialized: bool,   // Flag for completion
}
```

### Step 2: Create per-CPU idle task (smp.rs / scheduler)
- Each AP spawns one idle task
- Idle task: infinite loop, yields CPU
- Runs when no other task ready

### Step 3: Modify scheduler initialization
Add per_cpu_init() function that:
- Sets up per-core data structures
- Marks scheduler as ready
- Enables per-core timer tick

### Step 4: Integrate idle task spawning
During AP init:
```rust
unsafe extern "C" fn ap_entry(cpu: &Cpu) -> ! {
    // ... existing init ...
    
    // NEW: Initialize per-core scheduler
    let cpu_id = percpu::cpu_id();
    scheduler::init_per_cpu_scheduler(cpu_id);
    
    // NEW: Spawn and start idle task
    let idle_task = scheduler::spawn_idle_task(cpu_id);
    
    // Signal readiness
    AP_STARTED.fetch_add(1, Ordering::Relaxed);
    
    // NEW: Enter scheduler loop (never returns)
    scheduler::run();
}
```

### Step 5: Modify scheduler::run()
Make it per-CPU aware:
- Each CPU maintains its own run queue
- Idle task always available
- Timer tick increments per-CPU counter

## Safety & Correctness

### Per-CPU Isolation
- Each CPU has its own current_task
- No lock needed for "current"
- Scheduler lock only protects shared run queue

### Idle Task Design
- Prevents busy-waiting
- Allows CPU to sleep/halt if needed
- Must handle wake-up from other CPUs

### Error Handling
- AP fails init → timeout, BSP logs error
- Scheduler init fails → AP panics
- Task spawn fails → AP halts
